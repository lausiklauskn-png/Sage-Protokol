## Was getan

### Modul-Code

`src/modules/16_siegel.js` (~620 Zeilen, IIFE-Pattern analog Modul 15)
voll angelegt:

- **Public Surface** `window.SbkimSiegel = {init, isCertified,
  getExplanation, getCertifiedModules, getAspects, _meta}`.
- **`PFLICHT_MODULE`** als Modul-interne Konstante mit den sieben
  Spec-Einträgen (01 Storage / 02 Spore / 03 Embedding `lazy:true` /
  04 Match / 05 Anastomose / 07 Apoptose / 15 Membran).
- **`ZERTIFIKAT_ASPEKTE`** mit Start-Eintrag „Grund-Siegel-Bezeugung
  2026-05-24" (verbindlich aus Spec-Sitzung 16).
- **Surface-Check** im `init()` (Snapshot, gecacht in Closure):
  pro Eintrag `typeof globalThis[globalName]` + `typeof ns[surfaceFn]
  === "function"` → Status ∈ {"ok", "deferred", "missing", "broken"}.
  Re-Init no-op.
- **`isCertified()`** sync, true wenn alle Status ∈ {"ok", "deferred"}.
- **Binärer Fail-Modus:** bei missing/broken → genau EINE
  `console.warn`-Zeile mit ID-Liste, KEIN Badge, KEIN Modal. Wortlaut:
  `[SbkimSiegel] kein Render: Pflicht-Module fehlen/defekt — 04 (missing), 07 (broken). Siehe docs/components/16_siegel.md § Sub (a).`
- **Defensive Kopien** für alle Getter (analog Modul 15
  `fremdzugriff.list()`).
- **First-Boot-Animation** einmalig pro Session via `.first-boot`-
  Klasse + Setzen/Entfernen nach 600 ms. `_meta.firstBootShown` als
  Guard.
- **Repo-URL Auto-Erkennung** + Override mit Sanity-Check (Karte 16
  § Sub (c)).
- **KEINE benannten Error-Klassen** — alle Pfade fail-soft via
  `console.warn`.

### Bauzustands-Wahl Option β (Diskussion entschieden)

Spec-Brief 16 stellte zwei Optionen zur Wahl:

- **Option α:** Statisches `<span id="sbkim-siegel-badge">` in
  `index.html` einfügen, Modul-Code zeigt es per Klasse-Toggle.
- **Option β:** Modul erzeugt das Span-Element via JS im Container
  (`badgeSelector`), nur wenn `isCertified() === true`.

**Gewählt: Option β.** Begründung: Anti-Greenwashing-Klausel (Karte 16
§ Strikte Tabus: „kein DOM-Element überhaupt im Negativ-Fall") wird
binär erfüllt, ohne JS-getriebenen Cleanup-Pfad in Option α. Trade-off:
minimaler CSS-Layout-Shift bei spät-mountendem Badge, akzeptabel weil
Modul 16 in der Init-Kette spät kommt (nach Storage/Spore/etc.) und
die Lampen schon stehen.

Default-Selektor: `.lamps` (Container in der Navleiste). Modul setzt
den Span-Inhalt mit SVG-Wappen + `title`/`role="button"`/`tabindex`-
Attributen für a11y. Wenn der Selektor ein bereits-existierendes
Element mit `id="sbkim-siegel-badge"` matcht, nutzt das Modul es als
Anker (Rückwärts-Kompat für Endknoten, die später ihren Header-Badge
inline einbauen wollen).
